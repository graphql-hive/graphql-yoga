## Logging

Yoga uses 4 log levels `debug`, `info`, `warn` and `error`. By default, Yoga will only log `info`,
`warn` and `error` messages.

### Log Level Overview

#### `error`

- Only log unexpected errors

#### `warn`

- All prior log levels
- Yoga does not currently emit any automatic `warn`-level logs

#### `info`

- All prior log levels
- A one-line "Request processed" summary, logged once per HTTP request, carrying the method, path,
  `operationName` and `operationType` (or `batchedOperations` count for a batched request), the
  response status code, the GraphQL error count and the request's duration in milliseconds
- Background task events, for plugins that run one (e.g.
  [`useManagedFederation`](/docs/features/apollo-federation#using-apollo-managed-federation) logs
  when a new supergraph schema is loaded, or when it's retrying after a failed load)

#### `debug`

- All prior log levels
- Processing of GraphQL parameters, including the request path, `operationName`, variable count and
  the variables themselves
- Parsing of GraphQL parameters, and the resolved operation type
- The status code of the HTTP response that was sent
- A successfully fetched signing key in [`@graphql-yoga/plugin-jwt`](/docs/features/jwt)
- [GraphiQL](https://github.com/graphql/graphiql) rendering
- Health checks

### Correlating logs for a request

Every request is handled with its own child `Logger`, exposed as `context.log`, that carries a
`requestId` attribute. The id is taken from the incoming `x-request-id` header if present, or
generated otherwise, and is set on the outgoing response's `x-request-id` header. All log lines
produced while handling a given request — across parsing, parameters processing, execution and
response processing — carry this attribute, so they can be correlated together (e.g. when grepping
structured/JSON logs).

```ts
const yoga = createYoga({
  schema: createSchema({
    typeDefs: /* GraphQL */ `
      type Query {
        hello: String
      }
    `,
    resolvers: {
      Query: {
        hello: (_, __, context) => {
          context.log.debug('resolving hello')
          return 'world'
        }
      }
    }
  })
})
```

Configure (or disable) the request id with the `requestId` option:

```ts
import { createYoga } from 'graphql-yoga'
import { schema } from './my-schema.js'

const yoga = createYoga({
  schema,
  requestId: {
    // header to read the request id from, and to set on the response
    headerName: 'x-correlation-id',
    // used when the header is absent from the incoming request
    generateRequestId: ({ request, fetchAPI, context }) => fetchAPI.crypto.randomUUID()
  }
  // or `requestId: false` to not correlate requests at all
})
```
