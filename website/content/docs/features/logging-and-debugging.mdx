## Logging

Yoga uses 4 log levels `debug`, `info`, `warn` and `error`. By default, Yoga will only log `info`,
`warn` and `error` messages.

### Log Level Overview

#### `error`

- Only log unexpected errors

#### `warn`

- All prior log levels
- deprecation notices

#### `info`

- All prior log levels
- Information about the current state of the system

#### `debug`

- All prior log levels
- Processing of GraphQL parameters, including the request path, `operationName` and variable count
- Parsing of GraphQL parameters, and the resolved operation type
- Execution or subscription start
- Received GraphQL operation variables
- Execution or subscription end
- The status code of the HTTP response that was sent
- [GraphiQL](https://github.com/graphql/graphiql) rendering
- Health checks

### Correlating logs for a request

Every request is handled with its own child `Logger`, exposed as `context.logger`, that carries a
`requestId` attribute. The id is taken from the incoming `x-request-id` header if present, or
generated otherwise. All log lines produced while handling a given request — across parsing,
parameters processing, execution and response processing — carry this attribute, so they can be
correlated together (e.g. when grepping structured/JSON logs).

```ts
const yoga = createYoga({
  schema: createSchema({
    typeDefs: /* GraphQL */ `
      type Query {
        hello: String
      }
    `,
    resolvers: {
      Query: {
        hello: (_, __, context) => {
          context.logger.debug('resolving hello')
          return 'world'
        }
      }
    }
  })
})
```

### Enabling Debug Logging

<Callout>
  Instead, on JavaScript environments that support environment variables via `process.env` (e.g.
  Node.js), you can also conditionally enable `debug` logging by setting the `DEBUG` environment
  variable to `1`.
</Callout>

```ts title="Custom log level" {7}
import { createServer } from 'node:http'
import { createYoga } from 'graphql-yoga'
import { schema } from './my-schema.js'

const yoga = createYoga({
  schema,
  logging: 'debug'
})
```

### Change log level

You can customize the log lovel by passing on of the 4 levels to the `logging` option:

<Callout>
  We recommend not changing the default log level and only recommend changing it if you know what
  you are doing.
</Callout>

```ts title="Custom log level" {7}
import { createServer } from 'node:http'
import { createYoga } from 'graphql-yoga'
import { schema } from './my-schema.js'

const yoga = createYoga({
  schema,
  logging: 'warn'
})
```

Specifying the log level of `warn` will only log `warn` and `error` messages being logged.

### Custom logger

You can of course provide your own logger for piping to your favorite logging service/utility by
implementing a [`LogWriter`](https://the-guild.dev/graphql/hive/docs/logger) and passing it to a
`Logger` instance:

```ts
import { createServer } from 'node:http'
import { createYoga } from 'graphql-yoga'
import { Logger, LogWriter } from '@graphql-hive/logger'
import { logger } from './my-logger.js'
import { schema } from './my-schema.js'

class MyLogWriter implements LogWriter {
  write(level, attrs, msg) {
    // do stuff
  }
}

const yoga = createYoga({
  schema,
  logging: new Logger({ writers: [new MyLogWriter()] })
})

const server = createServer(yoga)

server.listen(4000, () => {
  console.info('Server is running on http://localhost:4000/graphql')
})
```

<Callout>
  `@graphql-hive/logger` ships writers for common logging libraries out of the box, e.g.
  `PinoLogWriter`, `WinstonLogWriter` and `LogTapeLogWriter`.
</Callout>

### Redacting Sensitive Data

Yoga logs `operationName` at the `info` level, and the full GraphQL operation variables at the
`debug` level, when processing a request. Since variables can carry sensitive data (passwords,
tokens, etc.), configure the
[`redact` option](https://the-guild.dev/graphql/hive/docs/logger/redacting) on your `Logger`
instance to mask known-sensitive field names before they're serialized:

```ts
import { createServer } from 'node:http'
import { createYoga } from 'graphql-yoga'
import { Logger } from '@graphql-hive/logger'
import { schema } from './my-schema.js'

const yoga = createYoga({
  schema,
  logging: new Logger({
    redact: ['variables.password', 'variables.token', 'variables.secret', 'headers.authorization']
  })
})
```

<Callout>
  Redaction paths must name known field keys ahead of time — they won't catch differently-named
  fields (e.g. `variables.userPassword`). Keep this list in sync with the sensitive fields in your
  schema's input types.
</Callout>

Further hook into the logging system by leveraging
[envelop](https://www.envelop.dev/plugins/use-logger)'s
[`useLogger`](https://www.envelop.dev/plugins/use-logger) plugin:

```ts
import { createServer } from 'node:http'
import { createYoga, useLogger } from 'graphql-yoga'
import { logger } from './my-logger'
import { schema } from './my-schema'

const yoga = createYoga({
  schema,
  plugins: [
    useLogger({
      logFn: (eventName, args) => {
        // Event could be execute-start / execute-end / subscribe-start / subscribe-end / etc.
        // args will include the arguments passed to execute/subscribe (in case of "start" event) and additional result in case of "end" event.
        logger.debug(eventName, ...args)
      }
    })
  ]
})

const server = createServer(yoga)

server.listen(4000, () => {
  console.info('Server is running on http://localhost:4000/graphql')
})
```
